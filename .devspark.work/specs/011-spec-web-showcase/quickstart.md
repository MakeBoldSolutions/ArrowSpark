# Quickstart: ArrowSpark Web Showcase (developer)

Temporary planning material. This describes the intended developer loop once implementation exists; commands refer to files the plan will create.

## Prerequisites

- **Godot 4.4-stable** editor and **4.4-stable export templates**, downloaded from the official GitHub release with SHA-512 verification (same source as CI). Do not use the 4.7.2 editor for exports or evidence.
- **Node 22 LTS** and npm.
- Python 3.11+ (existing launchers).

## 1. Game gates (unchanged, pinned version)

```sh
python tests/run_puzzle_regressions.py --godot <path-to-godot-4.4-stable>
python tests/run_regressions.py --godot <path-to-godot-4.4-stable>
<godot-4.4> --headless --editor --quit
```

All failure markers must be `0`, including the new content-version pin in `PUZZLE_CATALOG_FAILURES`.

## 2. Web export

```sh
<godot-4.4> --headless --path . --export-release "Web" web/public/game/index.html
```

Uses the committed `export_presets.cfg` "Web" preset (threads off). The output goes in `web/public/game/`, is git-ignored, and is regenerated by CI.

## 3. Site

```sh
cd web
npm ci
npm run check          # astro check + vitest + check-content.mjs
npm run dev            # http://localhost:4321  (reactions -> "temporarily unavailable" unless configured)
```

To use the mock reactions server:

```sh
npm run mock:reactions                  # http://localhost:8787/api/public/arrowspark/reactions
PUBLIC_REACTIONS_URL=http://localhost:8787 npm run dev
# mock modes: MOCK_MODE=accept|invalid|unavailable
```

## 4. Smoke checklist (browser)

Open `/play` and confirm:
- loading progress shows;
- the click focuses the game;
- the Reference Knot starts from Play;
- wheel/trackpad zoom changes the board, not the page;
- Fit, Pan and Open Move work;
- a blocked move counts as a mistake;
- completion shows results.

Then open devtools and confirm the bridge logged exactly one validated `attemptCompleted` event in development mode only; production builds log nothing.

Submit a game reaction with the mock in `accept`, `invalid` and `unavailable` modes, and check that gameplay is unaffected each time.

## 5. Production build

```sh
PUBLIC_REACTIONS_URL=https://makeboldspark.com npm run build   # web/dist
```

Deployment is by CI to Azure Static Web Apps (`arrow.makeboldspark.com`).
