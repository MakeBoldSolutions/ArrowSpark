## Findings

### INPUT1 — Restoring a remap discards unchanged bindings (CRITICAL)

- Principle III, Accessible, Configurable Controls: "Preserve keyboard/gamepad
  navigation and input remapping (MUST)."
- Location: `addons/maaacks_game_template/base/scripts/app_settings.gd:46–49`.
- Evidence:

  ```gdscript
  InputMap.action_erase_events(action_name)
  for config_event in config_events:
      if config_event not in action_events:
          InputMap.action_add_event(action_name, config_event)
  ```

- Trigger: defaults contain keyboard W plus a gamepad button; saved settings replace
  W with Q while retaining that gamepad button. The method clears every binding,
  then skips saved events also present in the original defaults.
- Observed in an isolated Godot run: `REMAP retained_gamepad=false binding_count=1`.
  Expected: Q and the gamepad button both remain. This affects restoration of saved
  mappings through `set_inputs_from_config()`, not merely a theoretical branch.
- Intent: restore the complete saved mapping without losing unchanged input methods.
- Repair: after clearing, restore every valid configured event; if deduplication is
  needed, compare against the newly populated map rather than the old defaults.
  Add a focused regression check for one changed and one unchanged binding, then
  smoke-test keyboard/gamepad controls and persistence across restart.

### SAVE1 — Failed save loading destroys the original file (CRITICAL)

- Principle VI, Preserve Saved Progress and Settings: "Changes MUST preserve existing
  saved progress and settings, or provide an explicit migration/reset plan when
  compatibility will break." It also rejects silent, unexplained loss of progress.
- Locations: `addons/maaacks_game_template/base/scripts/global_state.gd:23–45`;
  normal startup calls `GlobalState.open()` from
  `addons/maaacks_game_template/base/scenes/autoloads/app_config.gd:4`.
- Evidence: `_load_or_new()` logs a failed resource load, creates `GlobalStateData.new()`,
  and returns to `open()`, which immediately calls `save()` against the original path.
- Trigger: an existing save cannot be parsed. The audit wrote a sentinel to an
  isolated test save and called `GlobalState.open()`.
- Observed: `SAVE original_preserved=false overwritten_with_resource=true`.
  Godot emitted the expected parse/load errors, but the old bytes were still lost.
  This is an existing baseline defect; no claim is made that a recent commit introduced it.
- Intent: retain recoverable player data when loading fails and explain the failure.
- Repair: distinguish absent saves from failed loads. Preserve or quarantine the
  original before any write, surface a recover/reset choice, and avoid automatically
  saving fresh state over failed input. Validate missing, valid, corrupt, and
  incompatible saves with focused regression cases.

### KNOW6 — Save/progression behavior has no current knowledge document (MEDIUM)

- Audit structural requirement: site-audit step 5.12, knowledge coverage sweep.
  This is a framework coverage finding, not a claim that the constitution mandates
  a particular documentation layout.
- Evidence: `.knowledge/index.json` indexes only `arrowgame-constitution`, with
  no entities. Its broad `appliesTo` entries express governance, not system behavior.
- Behavior-bearing code: `scripts/game_state.gd:12–60` manages level states, current
  progress, and play count; `scripts/level_list_state_manager.gd:3–13` connects level
  selection/advancement to persisted progress.
- Repair: add a concise flat architecture/reference document describing ownership,
  save paths, startup/load/save/reset behavior, and known limitations; map it to the
  durable scripts and regenerate the knowledge index. An entity hierarchy is optional.
