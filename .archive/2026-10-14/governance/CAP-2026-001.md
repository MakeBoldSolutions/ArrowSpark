## Current State

Principle V, Practical Gameplay Verification:

> Web builds MUST also be verified in a browser: the affected gameplay is smoke-tested in each supported desktop browser, and the results, including checks not performed, are recorded the same way.

"Supported desktop browser" is not defined anywhere, so a verification record cannot be checked against it.

## Evidence

| Source | Finding | Count |
| ------ | ------- | ----- |
| PR review of #9 | CON-01: the rule needs a supported set to be checkable | 1 |

The PR verified Chrome, Firefox, the VS Code internal browser and Perplexity's browser, and had no way to say whether that satisfied "each supported desktop browser".

## Proposed Change

### Principle: V. Practical Gameplay Verification

Add to the web-build bullet: the supported desktop browsers are Firefox, Chrome, and browsers derived from Chrome (Chromium-based browsers, the "Chrome OS derivatives" family). A browser outside that set is not claimed as supported. Verification records name the browsers actually tested; a supported browser that was not tested is recorded as not tested.

**Rationale**: makes the existing MUST checkable without changing what it requires of a change.

## Impact Assessment

- **Existing Code**: none.
- **Future Development**: a gameplay change on a web build records Firefox and a Chromium-based browser at minimum, and says which supported browsers were not tested.
- **Tooling**: none.
- **Dependent documents**: `.knowledge/architecture/web-showcase.md` restates the verified browsers and must name the supported set.
